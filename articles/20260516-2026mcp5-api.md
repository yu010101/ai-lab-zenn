## はじめに：MCPサーバー選定が重要な理由

2026年、MCP（Model Context Protocol）はLLMと外部ツール・データソースを接続する事実上の標準プロトコルとなりました。Anthropicが2024年末にオープンソースとして公開したこのプロトコルは、AIエージェント開発のインフラレイヤーとして急速に普及しています。

しかし、GitHub上のMCPサーバー実装は2026年5月時点で数百を超え、どれを選べばよいのか判断が難しくなっています。本記事では、実務で特に利用価値の高い5つのMCPサーバーを**実際に導入・検証**し、アーキテクチャレベルまで掘り下げて解説します。

### 対象読者

- Claude Code、Cursor、Windsurf等のAIエディタを日常的に使うエンジニア
- AIエージェントの開発環境を整備したいテックリード
- MCPの内部動作を理解した上でツール選定したい方

### 対象MCPサーバー

| # | ツール名 | カテゴリ | 提供元 |
|---|----------|----------|--------|
| 1 | Context7 | ドキュメント参照 | Upstash |
| 2 | Playwright MCP | ブラウザ自動化 | Microsoft |
| 3 | PostgreSQL MCP | データベース操作 | Anthropic公式 |
| 4 | Sentry MCP | エラー監視連携 | Sentry |
| 5 | Firecrawl | Webスクレイピング | Firecrawl |

## MCPプロトコルの内部アーキテクチャ

ツール比較に入る前に、MCPの基盤技術を理解しておきましょう。MCPは**JSON-RPC 2.0**ベースのプロトコルで、クライアント（AIエディタ）とサーバー（ツール）間の通信を標準化します。

### 通信レイヤーの設計

MCPは2つのトランスポートをサポートしています：

1. **stdio（標準入出力）**: ローカルプロセスとして起動し、stdin/stdoutで通信。最も一般的
2. **HTTP + SSE（Server-Sent Events）**: リモートサーバーとの通信用。2026年に入り普及が加速

```typescript
// MCPサーバーの基本構造（TypeScript SDK）
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

const server = new McpServer({
  name: "my-mcp-server",
  version: "1.0.0",
});

// ツール定義: LLMが呼び出せる関数を登録
server.tool(
  "query_database",
  "Execute a SQL query against the connected database",
  {
    sql: { type: "string", description: "SQL query to execute" },
    params: { type: "array", description: "Query parameters", optional: true }
  },
  async ({ sql, params }) => {
    const result = await db.query(sql, params);
    return {
      content: [{ type: "text", text: JSON.stringify(result.rows, null, 2) }]
    };
  }
);

// stdioトランスポートで起動
const transport = new StdioServerTransport();
await server.connect(transport);
```

### MCPの3つのプリミティブ

MCPサーバーは以下の3種類のプリミティブを公開できます：

| プリミティブ | 制御主体 | 説明 |
|-------------|---------|------|
| **Tools** | LLM | LLMが判断して呼び出す関数（API呼び出し、DB操作等） |
| **Resources** | アプリケーション | ファイルやデータの読み取り専用アクセス |
| **Prompts** | ユーザー | 再利用可能なプロンプトテンプレート |

この設計により、LLMは自律的にツールを選択・実行しつつ、リソースから文脈情報を取得し、プロンプトでワークフローを定型化できます。

| 評価軸 | 説明 | 重み |

- **Tier 1（必須級）**: AIエージェント環境に入れない理由がない。費用対効果が圧倒的

## Tier 1: 必須級MCPサーバー

### 1. Context7 — ライブラリドキュメントをLLMに直接注入

#### 概要と技術的背景

Context7は、npmパッケージやフレームワークの**最新ドキュメント**をMCP経由でLLMのコンテキストに直接注入するサーバーです。Upstashが提供しており、バックエンドにはUpstashのサーバーレスインフラが使われています。

LLMの学習データカットオフによる「古い情報で回答してしまう」問題を根本的に解決します。

#### アーキテクチャ

Context7の内部動作は以下のフローです：

1. LLMがプロンプト内のライブラリ名を検出
2. Context7のAPIにリクエストを送信（`resolve`→`get_library_docs`）
3. Upstashのインデックスから該当ドキュメントのチャンクを検索
4. 関連性の高い部分をコンテキストとしてLLMに返却

ポイントは、ドキュメント全体ではなく**セマンティック検索で関連チャンクのみ**を返す設計です。これによりトークン消費を抑えつつ、必要な情報を正確に注入できます。

#### セットアップ

Claude Codeの場合、`~/.claude/settings.json`に以下を追加します：

```json
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp@latest"]
    }
  }
}
```

Cursorの場合は`.cursor/mcp.json`に同様の設定を記述します。APIキー不要で即座に利用開始できるのが大きな利点です。

#### 使い方の実例

プロンプトに`use context7`と付けるだけで、関連ドキュメントが自動的に参照されます：

```
Remixのloaderでcookieベースの認証を実装して use context7
```

これにより、LLMはRemixの最新ドキュメントを参照した上でコードを生成します。学習データに含まれない最新APIも正確に使えます。

#### 提供されるMCPツール

| ツール名 | 説明 |
|---------|------|
| `resolve` | ライブラリ名からContext7互換のIDを解決 |
| `get_library_docs` | 指定ライブラリのドキュメントチャンクを取得 |

#### 実務でのインパクト

- フレームワークのバージョンアップ直後でも正確なコード生成が可能
- 「その書き方は古いです」と指摘する手間が激減
- ドキュメントを別タブで開いてコピペする作業が不要に
- 対応ライブラリ数は数千規模で継続的に拡大中

### 2. Playwright MCP — AIエージェントにブラウザを与える

#### 概要と技術的背景

Microsoftが公式に提供するPlaywright MCPサーバーは、AIエージェントがブラウザを直接操作できるようにします。内部的にはPlaywrightのブラウザ自動化エンジンをMCPプロトコルでラップした実装です。

特筆すべきは、**Accessibility Tree（アクセシビリティツリー）ベース**でページを解釈する設計です。スクリーンショットではなく、ページのセマンティック構造をテキストとしてLLMに渡すため、トークン効率が高く、操作の精度も安定します。

#### アーキテクチャの詳細

```
[AIクライアント] → [MCP Protocol (JSON-RPC)] → [Playwright MCP Server]
                                                         ↓
                                              [Playwright Engine]
                                                         ↓
                                              [Chromium / Firefox / WebKit]
```

Playwright MCPは2つの動作モードを持ちます：

- **Snapshotモード（デフォルト）**: Accessibility Treeのスナップショットを取得。LLMフレンドリー
- **Visionモード**: スクリーンショットベース。視覚的なレイアウト確認に適する

#### セットアップ

Microsoft公式版：

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    }
  }
}
```

ブラウザのインストールが必要な場合：

```bash
npx playwright install chromium
```

#### 提供されるMCPツール（主要なもの）

| ツール名 | 説明 |
|---------|------|
| `browser_navigate` | 指定URLに遷移 |
| `browser_click` | 要素をクリック |
| `browser_type` | テキスト入力 |
| `browser_snapshot` | ページのAccessibility Treeを取得 |
| `browser_screenshot` | スクリーンショット取得 |
| `browser_wait` | 要素の出現を待機 |
| `browser_evaluate` | JavaScriptを実行 |

#### 使い方の実例

```
localhost:3000のログインページを開いて、
メールアドレスに test@example.com、パスワードに password123 を入力して
ログインボタンをクリックし、ダッシュボードが表示されることを確認して
```

AIエージェントがPlaywright MCPを通じて実際にブラウザを操作し、結果を報告してくれます。

#### E2Eテスト自動生成パターン

```typescript
// AIエージェントが生成するPlaywrightテストコードの例
import { test, expect } from '@playwright/test';

test('ログインフローが正常に動作する', async ({ page }) => {
  await page.goto('http://localhost:3000/login');
  
  await page.getByLabel('メールアドレス').fill('test@example.com');
  await page.getByLabel('パスワード').fill('password123');
  await page.getByRole('button', { name: 'ログイン' }).click();
  
  await expect(page.getByRole('heading', { name: 'ダッシュボード' })).toBeVisible();
  await expect(page).toHaveURL(/\/dashboard/);
});
```

#### 注意点

- ヘッドレスモードがデフォルト。UIを確認したい場合は`--headed`オプションを指定
- 認証が必要なページは事前にcookieやstorageStateの設定が必要
- ローカル開発サーバーへのアクセスが主な用途

### 3. PostgreSQL MCP — データベースをAIの文脈に接続

#### 概要と技術的背景

PostgreSQL MCPサーバーは、Anthropicが公式に提供するリファレンス実装の一つです。AIエージェントがPostgreSQLデータベースに直接クエリを発行し、スキーマ情報を参照できるようにします。

内部的には`pg`ライブラリ（node-postgres）を使用し、コネクションプーリングとクエリのサニタイズを行っています。

#### アーキテクチャ

```
[AIクライアント] → [MCP Protocol] → [PostgreSQL MCP Server]
                                            ↓
                                    [node-postgres (pg)]
                                            ↓
                                    [PostgreSQL Database]
```

重要な設計判断として、このサーバーは**READ ONLYモード**をデフォルトとしています。`SELECT`文のみ実行可能で、`INSERT`/`UPDATE`/`DELETE`は明示的に許可しない限りブロックされます。

#### セットアップ

```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-postgres",
        "postgresql://user:password@localhost:5432/mydb"
      ]
    }
  }
}
```

環境変数で接続情報を管理する場合：

```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "DATABASE_URL": "postgresql://user:password@localhost:5432/mydb"
      }
    }
  }
}
```

#### 提供されるMCPツール・リソース

| 種類 | 名前 | 説明 |
|------|------|------|
| Resource | `postgres://<host>/<table>/schema` | テーブルスキーマ情報 |
| Tool | `query` | SQLクエリの実行 |
| Tool | `list_tables` | テーブル一覧の取得 |
| Tool | `describe_table` | テーブル定義の詳細 |

#### 実務活用パターン

```sql
-- AIエージェントに依頼: 「直近7日の日別新規ユーザー数を出して」
-- 生成されるクエリ例:
SELECT 
  DATE(created_at) AS registration_date,
  COUNT(*) AS new_users
FROM users
WHERE created_at >= CURRENT_DATE - INTERVAL '7 days'
GROUP BY DATE(created_at)
ORDER BY registration_date;
```

```
# パフォーマンス調査
このクエリのEXPLAIN ANALYZEを実行して、ボトルネックを教えて

# orphanレコード検出
外部キー参照先が存在しない行がないか確認して

# マイグレーション生成
現在のスキーマを確認して、postsテーブルにtags配列カラムを追加する
マイグレーションファイルを生成して
```

#### セキュリティ上の注意

- **本番DBへの直接接続は避ける**。READ ONLY権限のレプリカまたはローカル開発DBを使用すること
- 接続文字列をコードにハードコードしない。環境変数で管理
- MCPサーバーの設定ファイルは`.gitignore`に追加してリポジトリに含めない

## Tier 2: 推奨MCPサーバー

### 4. Sentry MCP — エラー監視をAIワークフローに統合

#### 概要と技術的背景

Sentry MCPは、Sentryのエラー追跡・パフォーマンスモニタリングデータをAIエージェントのコンテキストに接続します。Sentry APIのラッパーとして動作し、Issue検索、イベント詳細取得、スタックトレース分析をMCPツールとして公開します。

#### なぜTier 2なのか

Sentryを使っているチームには非常に強力ですが、前提として「Sentryを既に導入している」必要があります。エラー監視ツールとしてSentryを使っていないチームには恩恵がありません。ただし、Sentryユーザーにとっては生産性向上の幅が大きいです。

#### セットアップ

```json
{
  "mcpServers": {
    "sentry": {
      "command": "npx",
      "args": ["-y", "@sentry/mcp-server"],
      "env": {
        "SENTRY_AUTH_TOKEN": "your-sentry-auth-token",
        "SENTRY_ORG": "your-org-slug"
      }
    }
  }
}
```

Sentry Auth Tokenは Settings > Auth Tokens から発行します。スコープは`event:read`, `project:read`, `org:read`が最低限必要です。

#### 提供されるMCPツール

| ツール名 | 説明 |
|---------|------|
| `list_issues` | 未解決のIssue一覧を取得 |
| `get_issue_details` | 特定Issueの詳細とスタックトレース |
| `search_errors` | エラーの検索（クエリ構文対応） |
| `get_event` | 特定イベントの完全な情報 |

#### 実践的なワークフロー

1. **朝のトリアージ**: 「昨日発生した新規エラーを一覧表示して」
2. **影響度分析**: 「このエラーの影響ユーザー数と発生頻度を教えて」
3. **根本原因特定**: 「スタックトレースからコードの該当箇所を特定して」
4. **修正実装**: 「このエラーを修正するコードを書いて」

エラー発見から修正までがAIエージェントの文脈内で完結します。

### 5. Firecrawl — WebページをLLMが理解できる形に変換

#### 概要と技術的背景

Firecrawlは、WebページをクロールしてMarkdownやStructured Dataに変換するツールです。内部的にはHeadless Chromiumでページをレンダリングし、JavaScript実行後のDOMからコンテンツを抽出します。

通常のHTTPリクエストでは取得できないSPA（Single Page Application）のコンテンツも確実に取得できる点が、単純なHTMLスクレイパーとの大きな違いです。

#### アーキテクチャ

```
[AIクライアント] → [MCP Protocol] → [Firecrawl MCP Server]
                                            ↓
                                    [Firecrawl API / Self-hosted]
                                            ↓
                                    [Headless Chromium] → [DOM解析]
                                            ↓
                                    [Markdown / Structured Data 出力]
```

#### セットアップ

```json
{
  "mcpServers": {
    "firecrawl": {
      "command": "npx",
      "args": ["-y", "firecrawl-mcp"],
      "env": {
        "FIRECRAWL_API_KEY": "your-api-key"
      }
    }
  }
}
```

セルフホスト版を使う場合：

```json
{
  "mcpServers": {
    "firecrawl": {
      "command": "npx",
      "args": ["-y", "firecrawl-mcp"],
      "env": {
        "FIRECRAWL_API_KEY": "your-api-key",
        "FIRECRAWL_API_URL": "http://localhost:3002"
      }
    }
  }
}
```

#### 提供されるMCPツール

| ツール名 | 説明 |
|---------|------|
| `scrape` | 単一ページをスクレイピングしてMarkdown化 |
| `crawl` | サイト全体を再帰的にクロール |
| `map` | サイトのURL構造をマッピング |
| `search` | Web検索してトップ結果をスクレイピング |

#### 活用シーン

| ユースケース | 具体例 |
|-------------|--------|
| 技術リサーチ | 外部APIドキュメントの読み込みと要約 |
| 競合分析 | 競合サービスの機能・価格ページの比較 |
| コンテンツ移行 | 旧サイトのコンテンツをMarkdownで抽出 |
| SEO分析 | ページ構造・メタ情報の一括取得 |

## ユースケース別おすすめ構成

### 個人開発者・最小構成

```json
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp@latest"]
    },
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]

```

**理由**: 最新ドキュメント参照 + ブラウザ動作確認。無料で始められる最小構成です。

### チーム開発・フルスタック構成

```json
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp@latest"]
    },
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    },
    "postgres": {
```

## MCPサーバー自作の基礎

既存のMCPサーバーで要件を満たせない場合、自作も現実的な選択肢です。TypeScript SDKを使えば、最小限のコードでMCPサーバーを構築できます。

### 最小実装例：GitHub Notifications MCPサーバー

```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({
  name: "github-notifications",
  version: "0.1.0",
});

// ツール: 未読通知の取得
server.tool(
  "get_notifications",
  "Fetch unread GitHub notifications",
  {
    filter: z.enum(["all", "participating", "mention"]).optional()
      .describe("Filter type for notifications"),
  },
  async ({ filter }) => {
    const token = process.env.GITHUB_TOKEN;
    if (!token) {
      return {
        content: [{ type: "text", text: "Error: GITHUB_TOKEN not set" }],
        isError: true,
      };
    }

    const params = new URLSearchParams();
    if (filter === "participating") params.set("participating", "true");

    const res = await fetch(
      `https://api.github.com/notifications?${params}`,
      { headers: { Authorization: `Bearer ${token}` } }
    );
    const notifications = await res.json();

    const summary = notifications.map((n: any) => 
      `- [${n.reason}] ${n.subject.title} (${n.repository.full_name})`
    ).join("\n");

    return {
      content: [{ type: "text", text: summary || "No unread notifications" }],
    };
  }
);

const transport = new StdioServerTransport();
await server.connect(transport);
```

この例のように、MCPサーバーの自作は「外部APIのラッパーをJSON-RPCで公開する」というシンプルな構造です。

## MCPサーバー導入のベストプラクティス

### 1. 設定ファイルの管理

プロジェクト固有のMCP設定はチームで共有しつつ、**APIキーは絶対にコミットしない**ことが鉄則です：

```gitignore
# .gitignore
.cursor/mcp.json
.mcp.json
```

チーム共有する場合はテンプレートを用意します：

```json
// .cursor/mcp.json.example
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "YOUR_DATABASE_URL_HERE"]
    }
  }
}
```

### 2. セキュリティの原則

- DBはREAD ONLYアカウントで接続する
- 本番環境のクレデンシャルをMCP設定に入れない
- Firecrawlで社内システムのURLをクロールしない
- Sentry Tokenのスコープは最小限にする

### 3. パフォーマンスの考慮

MCPサーバーはバックグラウンドプロセスとして常駐します。大量に追加するとメモリを消費するので、実際に使うものだけを有効化しましょう：

```bash
# 起動中のMCPサーバーのプロセスを確認
ps aux | grep mcp
```

### 4. トラブルシューティング

MCPサーバーが応答しない場合のデバッグ手順：

```bash
# 1. MCPサーバーを直接起動して動作確認
npx -y @upstash/context7-mcp@latest

# 2. stderrに出力されるログを確認
npx -y @modelcontextprotocol/server-postgres postgresql://... 2>&1

# 3. Claude Codeの場合、MCP接続状況を確認
# Claude Code内で /mcp コマンドを実行
```
