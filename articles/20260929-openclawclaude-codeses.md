## SESで働きながら「AIを使いこなす開発力」を武器にする

2026年現在、フリーランスエンジニアの単価交渉で問われるのは「何の言語が書けるか」だけではなくなってきた。むしろ「AIツールをどう組み合わせて、自分一人の生産性をチーム規模に引き上げられるか」が、クライアントに提示できる説得材料になりつつある。

SES企業に常駐しながら独立準備を進めているエンジニアの多くは、案件で使える技術スタックが限定されがちで、AI駆動開発の実践機会を業務の外で作る必要がある。本記事では、「思考・記憶・指示」を担うOpenClawと、「開発・実行」を担うClaude Codeを連携させた実践例を、実際に使えるコマンドと設定を交えて紹介する。個人開発やポートフォリオ構築、独立後の運用効率化にそのまま応用できる内容にした。

## OpenClawとClaude Codeの役割分担を整理する

両者を混同して使うと「何でも1つのチャットで済ませる」状態になり、長期運用では破綻しやすい。役割を明確に分けるのがポイントだ。

| レイヤー | 担当 | 具体例 |
|---|---|---|
| OpenClaw | 思考・記憶・指示 | 長期記憶(メモリファイル)の保持、タスクのスケジューリング、意思決定の判断基準の管理 |
| Claude Code | 開発・実行 | コード生成、テスト実行、ファイル編集、CLI経由でのビルド・デプロイ |

OpenClaw側は「何を」「いつ」「どんなルールで」実行するかを決める頭脳、Claude Codeは実際に手を動かす実行部隊、というイメージで運用するとワークフローが整理しやすい。

## 実践例1: 日次トレンド調査→記事下書き生成パイプライン

個人開発でブログやポートフォリオ記事を継続的に書くのは、独立準備において地味だが効果の大きいタスクだ。ここではOpenClawが「今日調べるべきトピックとルール」を保持し、Claude CodeのHeadlessモード(`-p`オプション)で実行する構成を例に紹介する。

```bash
# crontab例: 平日朝にトレンド調査→下書き生成を自動実行
0 8 * * 1-5 cd ~/projects/blog-automation && \
  claude -p "$(cat prompts/daily_trend_research.md)" \
  --output-format json >> logs/daily_$(date +\%Y\%m\%d).log 2>&1
```

`prompts/daily_trend_research.md` の中身は、OpenClaw側が管理する「記憶」を反映したプロンプトになっている。たとえば以下のような指示だ。

```markdown
# daily_trend_research.md
1. Qiita/Zennの直近トレンドタグを確認する
2. 過去記事のパフォーマンスデータ(memory/にある記録)と照らし合わせる
3. 同じ切り口が3回続いていたら別角度を提案する
4. 下書きはJSON形式で /drafts/ に保存し、人間承認前は絶対に公開しない
```

ポイントは「人間承認前は絶対に公開しない」という一文を明示的にルール化しておくことだ。無人実行のパイプラインでは、生成だけを自動化し、公開判断は必ず人間に残す設計が事故防止の基本になる。

## 実践例2: 役割別サブエージェントで「一人経営」を回す

Claude Codeにはサブエージェント機能があり、タスクごとに専門化したエージェントを呼び分けられる。フリーランスとして独立すると、開発以外にも経理・営業・進捗管理といった「経営業務」が発生するが、これをサブエージェントで役割分担すると一人でも運用が回しやすくなる。

```bash
# .claude/agents/ 配下にエージェント定義を置く例
.claude/agents/
  ├── deploy-verifier.md   # デプロイ前の差分検証専任
  ├── site-auditor.md      # SEO/構造化データの定期監査
  └── research-scout.md    # 市場調査・競合調査を独立コンテキストで実施
```

各エージェントは独立したコンテキストで動くため、メインの会話ウィンドウを汚さずに並列で調査やチェックを走らせられる。これはSESの案件でいう「レビュー担当を分ける」感覚に近く、一人でも品質を落とさずに開発速度を維持する工夫として機能する。

## 実践例3: 無人運用を安全に回すための設計

OpenClaw×Claude Codeの組み合わせが強力なのは、cronなどで無人実行できる点だが、それゆえに安全設計が重要になる。実践で有効だったルールの一例を挙げる。

- **SNS投稿の連投間隔を強制する**: 同一アカウントへの短時間連投はプラットフォーム側のアカウント制限リスクがあるため、投稿系タスクには最低限の間隔ルールをOpenClaw側のポリシーとして明文化しておく
- **生成は下書きまで、公開は人間承認**: 自動化するのは「作る」工程までにとどめ、「出す」工程には人の目を必ず挟む
- **常駐プロセスの監視**: cronやlaunchdは無音で停止することがあるため、PM2のようなプロセスマネージャーで死活監視をかけておく
- **クリーンな状態からのビルド**: 未コミットの変更が残った状態でデプロイしない。差分を必ず確認してから実行する

こうしたルールは、Claude Codeの`CLAUDE.md`のようなプロジェクト設定ファイルに明文化しておくと、AI側が毎回参照して自律的に守るようになる。

この種のトレンドが示すのは、個人開発・小規模運用でも「サーバーレス+エッジ環境+軽量フレームワーク」の組み合わせでコストを極小化しながら高品質なプロダクトを作れる時代になっているということだ。フリーランスとして独立する際、インフラコストを抑えつつ品質を担保できる技術選定ができるかどうかは、そのまま利益率に直結する。OpenClaw×Claude Codeのような開発体制と、Cloudflareのようなほぼ0円運用可能なインフラを組み合わせる発想は、独立後の固定費を抑える上で実務的に価値がある。

## この開発力がフリーランス単価・年収にどう効くか

SESの単価は基本的に「稼働時間×スキル単価」で決まる構造だが、フリーランスの単価は「成果に対してどれだけ価値を出せるか」で決まる比重が大きくなる。エンジニア市場データ分析の観点で見ても、クライアント企業がフリーランスに求めるのは「言われたことをやる」ではなく「自走して成果を出す」力だ。

OpenClaw×Claude Codeのような構成を自分で組んで運用できることは、以下のような形で単価交渉の材料になり得る。

- 開発だけでなく運用・監視まで一人で設計できる証明になる
- 無人運用の安全設計ができることは、そのまま「事故を起こさない」信頼材料になる
- 個人開発の実績(記事、ツール、自動化パイプラインなど)がポートフォリオになる

年収やフリーランス単価は案件内容やスキルセットによって大きく変動するため、具体的な相場水準はここでは断定しないが、「AIツールを設計・運用できる」というスキルセット自体が、今後のエンジニア市場データ分析において重要な差別化要因になっていくことは間違いない。

## エンジニア独立準備チェックリスト(保存推奨)

SESからフリーランスへの独立準備として、OpenClaw×Claude Codeの実践を通じて確認しておきたい項目をチェックリストにまとめた。

| チェック項目 | 目的 |
|---|---|
| □ CLAUDE.md(または同等の設定ファイル)にプロジェクトルールを明文化した | AIが毎回文脈を再学習しなくて済む状態を作る |
| □ サブエージェントで役割(開発/監査/調査)を分離した | 一人でもレビュー品質を担保する |
| □ cronなどの無人実行に「公開前の人間承認」を必ず挟んだ | 誤公開・誤送信事故を防ぐ |
| □ 常駐プロセスの死活監視を設定した | 無音停止による運用停止を防ぐ |
| □ デプロイ前に差分検証のステップを入れた | 未コミットWIPの混入を防ぐ |
| □ 個人開発の成果物をポートフォリオとして残す仕組みを作った | 単価交渉時の実績材料にする |
| □ インフラコストを抑える技術選定(エッジ/サーバーレス)を検討した | 独立後の固定費を圧縮する |

このリストは一度作って終わりではなく、案件や運用規模が変わるたびに見直す前提で使うとよい。

## まとめ

OpenClaw(思考・記憶・指示)とClaude Code(開発・実行)を役割分担して連携させることで、個人でも「作る」だけでなく「運用を安全に回す」体制が構築できる。SES企業に所属しながらでも、こうした自動化パイプラインやマルチエージェント運用を個人開発で試すことは、独立準備そのものになる。

単価や年収は最終的にはスキルと実績次第だが、AI駆動開発を自分の手で設計・運用できるというスキルセットは、これからのエンジニア市場データ分析においてますます重視されていくはずだ。まずは小さな自動化パイプラインを一つ、自分の手で組んでみることから始めてみてほしい。
