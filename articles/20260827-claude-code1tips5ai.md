# Claude Codeを1年ガチ運用して分かった「実務で使えるTips」5選 データ分析からキャリア戦略まで

## はじめに:SES現場でもAIツールは「使える人」と「使えない人」が分かれ始めている

2026年8月現在、Claude CodeをはじめとするAIコーディングエージェントは、もう「試しに触ってみるツール」の段階を過ぎた。自分自身、常駐先の業務でもフリーランス案件でも、毎日ターミナルを開いたら真っ先にClaude Codeを起動する生活を続けている。

この記事では、実際に自分の環境で動かしているコマンドや設定ファイルをベースに、Claude Codeの実務Tipsをまとめる。あわせて、SESエンジニアが意識しておきたい「データ分析スキル」「年収」「フリーランス 独立 準備」「SES 1年目 転職」というテーマにも触れていく。架空の体験談や検証不能な数字は書かない。実際に手を動かして確認できる内容だけを書く。

## Claude Codeとは何か(2026年時点のおさらい)

Claude CodeはAnthropic製のCLIベースのコーディングエージェントで、ターミナル上で自然言語による指示からコード編集・実行・テスト・Git操作までをこなす。現在はSonnet 5やOpus 5系のモデルをバックエンドに選べるようになっており、単なる「コード補完」ではなく、タスクを分解して自律的に進める「エージェント」としての性格が強くなっている。

自分が実務で特に効いていると感じているのは以下の5つの機能だ。

## 実務Tips1: CLAUDE.mdでルールを固定化する

プロジェクト直下、もしくはホームディレクトリの `~/.claude/CLAUDE.md` にルールを書いておくと、Claude Codeは毎回そのルールを読み込んでから動く。

```markdown
## Core Principles
- Simplicity First: 変更は最小限に
- No Laziness: 根本原因を探る。一時しのぎの修正はしない
- Minimal Impact: 必要な箇所以外は触らない
```

これをプロジェクトごとに用意しておくと、「勝手にリファクタリングされて差分が膨らむ」「コメントを大量に書かれる」といった事故がかなり減る。SES案件で複数の常駐先を掛け持ちしている場合、案件ごとにCLAUDE.mdのルールを変えておけば、現場のコーディング規約に合わせた挙動をさせやすい。

## 実務Tips2: サブエージェントで調査とコーディングを分離する

Claude Codeには「Agent(サブエージェント)」という仕組みがあり、探索・レビュー・実装を別々のエージェントに任せられる。例えばコードベースの構造を把握したいだけなら、メインの会話コンテキストを汚さずに調査系のエージェントに検索を投げる、という使い方をしている。

体感として一番効くのは、「大きな調査タスクをメインの会話から切り離せる」ことだ。メインのコンテキストウィンドウが調査結果で埋まってしまうと、その後の実装フェーズで手戻りが増える。調査はサブエージェントに任せ、要約だけをもらう運用にしてから、長時間セッションでの精度低下を感じにくくなった。

## 実務Tips3: hooksでコマンド実行を自動チェックする

`.claude/settings.json` にhooksを設定すると、Claude Codeがツールを呼び出すタイミングで任意のシェルコマンドを差し込める。自分の環境では、危険なコマンド(`rm -rf` や `git push --force` など)が実行される前に警告を出すフックを入れている。

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "echo 'コマンド実行前チェック' >> ~/.claude/audit.log"
          }
        ]
      }
    ]
  }
}
```

無人実行(cronでの自動タスクなど)をさせる場合、このhooksによる監査ログは地味に効く。「何を勝手に実行したか」を後から追跡できるようにしておくことは、AIエージェントに裁量を持たせるほど重要になる。

## 実務Tips4: Plan Modeで大きな変更を安全に進める

3ステップ以上かかる非自明なタスクや、設計判断を伴う変更は、いきなり実装させずにPlan Mode(計画モード)を使う。Claude Codeにまず設計方針だけを出させて、その内容を確認してから実装に進ませる、という2段階の運用にすると、手戻りが大きく減る。

個人的な運用ルールとして、

- 3ファイル以上にまたがる変更 → 必ずPlan Modeを通す
- 1ファイルの軽微な修正 → Plan Modeはスキップして直接依頼

という線引きをしている。すべてを計画モード経由にすると逆にスピードが落ちるので、変更の影響範囲で使い分けるのがポイントだ。

## 実務Tips5: Skill機能でワークフローをテンプレ化する

繰り返し行う定型作業(SEO監査、コードレビュー、デプロイ前チェックなど)は「Skill」としてテンプレート化しておける。一度書いてしまえば、スラッシュコマンドで呼び出せるようになる。

毎回同じ手順を口頭(というかテキスト)で説明し直すのは非効率なので、定型業務が3回以上発生した時点でSkill化する、というのを自分ルールにしている。

## データ分析業務でClaude Codeを使ってみた

SESの現場でも、ログ解析やアクセス解析といった「データ分析」を求められる場面は増えている。Claude Codeはコード生成だけでなく、実際にPythonスクリプトを実行してその場で結果を確認できるのが強みだ。

例えば、CSVログの異常値を調べたいとき、自分は次のような投げ方をしている。

```bash
# ログファイルをClaude Codeに渡して分析を依頼する例
claude "access_log.csv を読み込んで、1分あたりのリクエスト数の
分布を集計し、外れ値と思われる時間帯を教えて。
pandasのコードも見せて"
```

Claude Codeは実際にpandasのコードを書いて実行し、結果を見ながら修正するところまで自律的に行う。人間が手でコードを書いてデバッグするより、この往復が圧倒的に速い。

データ分析スキルは、SESエンジニアが「作業者」から「提案できる人材」に変わるための分水嶺になりやすい分野だと感じている。単体テストを書く、指示された機能を実装する、という受け身の仕事に加えて、「このログから何が言えるか」を自分の言葉でまとめられると、常駐先での評価のされ方が変わる。AIツールを使えば、SQL・pandas・可視化のコードを書く部分のハードルは大きく下がっているので、あとは「何を分析するか」を考える側に回れるかどうかが差になる。

## SES 1年目からの転職準備で意識していること

SES 1年目のうちは、現場によって扱う技術がバラバラで、スキルの軸が定まりにくい。自分がこの時期に意識していたのは、現場の技術スタックに依存しない「共通スキル」を並行して育てることだった。

- Gitでの差分管理・コミット粒度の設計
- 障害調査で使うログ読解・仮説検証の型
- AIツールを使った調査・実装の高速化(これは現場を選ばず使える)

転職活動でアピールしやすいのは、特定言語の熟練度よりも「未知の技術スタックに放り込まれても自走できる」ことの証明だ。Claude Codeのようなツールを使って、初見のコードベースを短時間で把握し、修正案まで出せるようになっておくと、面接で「新しい環境への適応力」を具体的なエピソードとして語れるようになる。

## フリーランス 独立 準備として今からやっておくべきこと

SESからフリーランスへの独立を考えるなら、「一人で全工程を回せるか」が最初の壁になる。要件整理、設計、実装、テスト、デプロイ、そして請求書のやり取りまで、これまでチームで分担していた作業を一人でこなす必要が出てくる。

AIエージェントをうまく使えば、この「一人で全部やる」負荷を相当下げられる。自分が独立準備として実際にやっていることは以下の通り。

1. **個人開発でCLAUDE.mdやSkillを整備する**:業務外で自分専用の開発環境を作り込んでおくと、独立後すぐに同じワークフローを使い回せる
2. **請求・契約まわりのドキュメントをAIに整理させる**:見積書のテンプレート化、契約書の論点整理など、非エンジニア業務もAIに下書きさせて時間を圧縮する
3. **複数案件を並行管理する仕組みを作る**:タスク管理やスケジュールの棚卸しをAIに定期的にやらせる

独立後は「技術力」だけでなく「一人で全部を回す運用力」が問われる。AIツールはその運用力を底上げする手段として使うのが現実的だ。

## 年収を上げるために考えていること

年収を上げる方法として即効性があるのは「単価の高い案件に移る」ことだが、それだけでは頭打ちになる。中長期的に効くのは、AIツールを使って「一人あたりの生産性」を上げ、より難易度の高い仕事を任される状態を作ることだと考えている。

同じ工数で対応できる範囲が広がれば、常駐先での評価や次の契約条件の交渉材料になる。逆に、AIツールを使わずに従来通りのペースで作業を続けていると、相対的な生産性の差が開いていく可能性がある。ここは市場データではなく自分の実感ベースの話だが、少なくとも「AIエージェントを実務でどう使うか」を語れること自体が、面談や商談での評価材料になっている感覚はある。

## まとめ

Claude Codeは単なる補完ツールではなく、CLAUDE.md・サブエージェント・hooks・Plan Mode・Skillといった機能を組み合わせることで、実務のワークフローそのものを変えるツールになっている。SESエンジニアにとっても、データ分析のような「作業者から提案者へ」の橋渡しになるスキルを、AIの力を借りて短期間で身につけられる環境が整ってきた。

SES 1年目の転職準備でも、フリーランス独立の準備でも、年収を上げる交渉材料としても、「AIエージェントをどう実務に組み込んでいるか」を具体的に語れることが、これからますます差別化要因になっていくはずだ。まずは自分の手元のCLAUDE.mdを1つ書いてみるところから始めてみてほしい。
